# 03. 運作機制：Loop 與 Graph 工作流設計

AI Agent 之所以能完成複雜任務，關鍵在於它不是「單次生成」，而是透過 **迴圈（Loop）** 或 **狀態圖（Graph）** 不斷迭代。

## ReAct 經典迴圈（Reason + Act）
1. **Thought（思考）**：分析目前進度與缺失。
2. **Action（行動）**：決定呼叫某個工具或生成草稿。
3. **Observation（觀察）**：取得工具回傳結果或檢查器（Validator）的評估。
4. **Loop 判斷**：若未達標則回到 Thought 修正；若通過則進入下一階段。

## 為什麼需要 Graph（狀態圖）與檢查節點？
單純的無限迴圈容易陷入「死胡同」或產生「幻覺（Hallucination）」。透過 **Graph（有向圖）** 設計，我們可以明確定義：
- **節點（Nodes）**：每個節點負責單一職責（例如：檢索資料、草擬內容、事實核對、格式檢查）。
- **條件邊（Conditional Edges）**：在檢查節點設定門檻（例如：必須 100% 引用 Wiki 來源）。若檢查不通過，條件邊會將狀態打回上一個生成節點重做，直到通過才放行。
